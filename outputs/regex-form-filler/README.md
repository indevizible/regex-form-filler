# Regex Form Filler

ส่วนขยาย Manifest V3 สำหรับ Opera / Chromium จับคู่ **ชื่อคำถาม** ของ Google Forms แล้วกรอกช่องว่างตามกฎที่คุณบันทึก มีตัวช่วยสร้างกฎภาษาไทยโดยไม่ต้องเขียน Regex หรือ JSON ไม่มี build step, dependency, เซิร์ฟเวอร์ หรือ telemetry ของส่วนขยาย ไม่กด Submit / ส่ง และลองกด Next ได้เฉพาะคีย์ลัดเมื่อเปิดตัวเลือก

## ติดตั้งใน Opera

1. เก็บโฟลเดอร์ `regex-form-filler` ไว้ในตำแหน่งถาวรที่มี `manifest.json` อยู่ข้างใน หากได้รับเป็น ZIP ต้องแตกไฟล์ก่อน **ห้ามลบหรือย้ายโฟลเดอร์หลังติดตั้ง**
2. เปิด `opera://extensions` แล้วเปิด **Developer mode**
3. กด **Load unpacked** แล้วเลือกโฟลเดอร์ `regex-form-filler` (ไม่ใช่ไฟล์ ZIP หรือโฟลเดอร์ชั้นนอก)
4. ปักหมุด Regex Form Filler ที่แถบเครื่องมือเพื่อเปิดหน้าต่างตั้งค่าได้ง่าย
5. Chromium / Chrome ใช้ขั้นตอนเดียวกันที่ `chrome://extensions`

อัปเดตแบบ Load unpacked เป็น 1.6.3: รอให้งานปัจจุบันจบ คัดลอกไฟล์เวอร์ชันใหม่รวม `presets.js` และโฟลเดอร์ `icons/` ทับไฟล์ใน **โฟลเดอร์เดิมที่ใช้ติดตั้ง** แล้วกด **Reload** ของ Regex Form Filler ที่ `opera://extensions` (Chrome ใช้ `chrome://extensions`) เปิด popup ใหม่และตรวจว่าส่วนหัวแสดง **เวอร์ชัน 1.6.3** กฎเดิมจะแสดงเป็นชุด **ค่าเริ่มต้น** และสำเนาไฟล์ใน IndexedDB ยังอยู่ ไม่ต้องนำเข้าใหม่ **ห้ามถอนส่วนขยายแล้วติดตั้งใหม่ ห้ามล้างข้อมูลส่วนขยาย**

**1.6.3** ให้การค้นหา picker และการรอ UI นิ่งใช้เวลางานไฟล์เดิมร่วมกับการยืนยันอัปโหลด: ไม่เกิน 60 วินาทีต่อไฟล์และ 180 วินาทีต่อครั้ง แทนเพดานค้นหาแยก 10 วินาที ยังคงรอ UI นิ่งอย่างน้อย 1 วินาที ส่งไฟล์ครั้งเดียวตามลำดับ และไม่ขยายเวลารอปิด picker การยกเลิกหรือเปลี่ยน frame/dialog/เจ้าของฟอร์มระหว่างโหลดจะหยุด มีแพ็กเกจ Chrome และ Opera ใน GitHub Release; Chrome ZIP ส่งเข้า Chrome Web Store แบบ Unlisted แล้วและรอรีวิว ณ 16 ตุลาคม 2026

ข้อจำกัด: รองรับเฉพาะรูปแบบ picker ที่สังเกตเห็นช่องไฟล์แรกถูกแทนด้วยช่องไฟล์ว่างใหม่เพียงช่องเดียวที่เชื่อมต่ออยู่ใน document/dialog เจ้าของเดิม เริ่มสังเกตระหว่าง loading/interactive เมื่อยืนยัน same-origin `/picker` จริงแล้ว แต่เริ่มรอนิ่งและส่งไฟล์ได้หลังโหลดครบเท่านั้น การเปลี่ยน document/dialog หลังเริ่มสังเกตจะหยุด หากพลาดการเปลี่ยนช่องหรือ Google ใช้รูปแบบอื่น จะหมดเวลาด้วย `picker-initialization-not-observed` (ยังไม่ได้ส่งไฟล์ ให้เลือกเอง) การเปลี่ยนช่องร่วมกับเวลานิ่งไม่ใช่สัญญาณยืนยันว่า controller ภายใน Google พร้อม และไม่มีการลองอัปโหลดซ้ำอัตโนมัติ ผลการทดสอบและส่วนที่ยังไม่ได้ตรวจอยู่ท้ายคู่มือนี้

**1.6.1 ปรับเฉพาะไอคอนให้ใหญ่ขึ้นบนแถบเครื่องมือ** ขยายรูปเอกสารสีมิ้นต์พร้อมเครื่องหมายถูกเดิมโดยลดพื้นที่ว่างรอบภาพ ใช้ PNG ขนาด 16, 32, 48 และ 128 พิกเซลที่เส้นทางเดิม ไม่มีการเปลี่ยนฟีเจอร์ พฤติกรรม สิทธิ์ คีย์ลัด หรือข้อมูลที่เก็บไว้

**1.6.0 เพิ่มชุดกฎที่ตั้งชื่อได้** บันทึกสำเนาชุด เลือกชุด เปลี่ยนชื่อ และลบชุด โดยคงสิทธิ์ คีย์ลัด และโค้ดกรอก/อัปโหลดเดิม

**1.5.6 เพิ่มไอคอนส่วนขยายและแถบเครื่องมือ** ขนาด 16, 32, 48 และ 128 พิกเซลจากภาพต้นฉบับเดียวกัน คงคีย์ลัด **Option+Shift+F บน macOS / Alt+Shift+F บน Windows และ Linux** สิทธิ์ และโค้ดกรอก/อัปโหลดจาก 1.5.4 ทั้งหมด ประวัติ ณ 14 ตุลาคม 2026: v1.5.6 ส่ง Chrome Web Store แล้วและรอรีวิว; Opera Add-ons ยังไม่ได้ส่ง สถานะนี้เป็นของ v1.5.6 เท่านั้น

การติดตั้งจากสโตร์อาจใช้ ID/พื้นที่เก็บข้อมูลคนละชุดกับ Load unpacked หรืออีกเบราว์เซอร์หนึ่ง ไม่รับประกันว่าจะย้ายกฎหรือไฟล์ให้เอง หากย้ายไปคนละโปรไฟล์/ID ให้ส่งออกกฎก่อน แล้วนำเข้าและเลือกไฟล์ใหม่ในปลายทาง JSON ไม่มี bytes ของไฟล์ และไม่ย้ายสำเนาไฟล์ข้ามโปรไฟล์

**1.5.5 คืนคีย์ลัดเริ่มต้น macOS เป็น Option+Shift+F** ส่วน Windows / Linux ยังคงเป็น **Alt+Shift+F** คงโค้ดแก้อัปโหลดจาก 1.5.4 สิทธิ์ กฎ และการเก็บไฟล์เดิมทั้งหมด การติดตั้งเดิมอาจเก็บคีย์ลัดที่ตั้งไว้ ให้ตั้ง **Option+Shift+F** เองใน Opera **Extensions → Keyboard shortcuts** ได้โดยไม่ต้องถอนส่วนขยาย

**1.5.4 แก้การรอ dialog ความคืบหน้าระหว่างอัปโหลด** หลังรับไฟล์ Google สร้าง inner dialog ใหม่เป็น sibling และใส่ `aria-hidden=true` ให้ wrapper ของ Insert file เดิม รุ่นก่อนหยุดด้วย `picker-ui-changed` จึงไม่เริ่มไฟล์ข้อถัดไป รุ่นนี้รอการเปลี่ยน UI ภายใน document เดิมได้ โดยยังตรวจ outer dialog/iframe ที่เปิดเอง ต้นทางเดียวกัน และฟอร์ม/คำถาม/รายการเดิม ต้องปิด picker คืนการมองเห็นฟอร์ม และพบชื่อไฟล์ตรงก่อนเริ่มข้อถัดไป ไม่คลิก UI ใหม่; ปุ่ม Insert ใช้ได้เฉพาะ UI เดิมที่กลับมาตรง guard และเลือกชื่อไฟล์ตรงเท่านั้น คง timeout, จำนวนครั้งที่ลอง, การกำหนดไฟล์/ส่ง event, เงื่อนไข Next และ diagnostics จาก 1.5.3

ผลไฟล์ที่ไม่สำเร็จจะแสดงคำอธิบายไทยพร้อมรหัสคงที่ เช่น `picker-document-changed`, `close-grace-expired` หรือ `previous-unconfirmed` (ข้ามเพราะไฟล์ก่อนหน้ายังยืนยันไม่ได้) กรณีหยุดก่อนส่งไฟล์หรือเกิดข้อผิดพลาดจะแสดงขั้นตอนที่หยุด ใช้เฉพาะรหัสใน allowlist ของ `core.js` ไม่มีประวัติ event หรือข้อความ DOM เพิ่มเติม ไม่บันทึก URL/query/auth, คำตอบ, ชื่อไฟล์, bytes หรือรายละเอียด exception ใน diagnostics รายงานเก่าที่ไม่มีรหัสยังอ่านได้

`picker-discovery-timeout` หมายถึงหมดเวลาก่อนค้นพบ picker ที่โหลดพร้อม ส่วน `picker-settling-timeout` หมายถึงหมดเวลารอ UI นิ่ง ทั้งสองกรณียังไม่ได้ส่งไฟล์ `overall-timeout` ยังคงใช้เมื่อหมดเวลารวม หรือหมดเวลารอยืนยันหลังส่งไฟล์ รหัสทั่วไป `picker-discovery` ยังใช้กับ guard/ข้อผิดพลาดอื่นและไม่ได้ระบุสาเหตุแน่นอน

หลังทดสอบ ให้ตรวจ **ผลล่าสุดของแท็บนี้** ซึ่งแสดงวันเวลารายงานและเวอร์ชันที่รัน แยกจากเวอร์ชันที่โหลดอยู่ในส่วนหัว รายงานเก่าอาจยังแสดงหลัง Reload; ต้องรันใหม่เพื่อได้ผลของ 1.6.3 จดรหัสเหตุผลของไฟล์แรกและไฟล์ที่สองพร้อมเวอร์ชัน/วันเวลาเพื่อใช้หาสาเหตุ โดยไม่ต้องส่งไฟล์หรือคำตอบส่วนตัว

1.5.1 แก้สถานะ stale เมื่อ Google Forms ใส่ `aria-hidden` ให้ฟอร์มขณะเปิด Insert file ยอมรับเฉพาะการบังด้วย ARIA บนฟอร์ม/บรรพบุรุษเดิมเมื่อยืนยัน picker ใหม่ที่ถูกต้องแล้ว ยังตรวจตัวตนคำถาม/ช่องกรอก รอ picker โหลดครบ และยืนยันชื่อไฟล์พร้อมปิด picker และคืนการมองเห็นฟอร์มก่อนสำเร็จหรือ Next

1.5.2 ปรับการรอเมื่อ picker นำ input ออกหลังรับไฟล์ หรือคืน ARIA ของฟอร์มช้ากว่าการปิด picker โดยรอชื่อไฟล์ตรงและฟอร์มเดิมกลับมามองเห็นภายใน 5 วินาทีหลังปิด ก่อนอัปโหลดข้อว่างถัดไป ไม่ส่งไฟล์ซ้ำ และลอง Next หลังยืนยันครบทุกข้อเท่านั้น ผลนี้ผ่านการจำลอง แต่ยังไม่ยืนยันว่าแก้อาการที่ผู้ใช้พบจริง

## ชุดกฎที่ตั้งชื่อได้

แผง **ชุดกฎที่ใช้** อยู่เหนือปุ่มกรอก เลือกชุดจาก dropdown แล้วจะจำการเลือกไว้สำหรับ popup ครั้งถัดไปและคีย์ลัด พิมพ์ชื่อแล้วกด **บันทึกเป็นชุดใหม่** เพื่อคัดลอกกฎที่บันทึกของชุดปัจจุบันและเลือกสำเนาทันที การเพิ่ม แก้ ลบกฎ หรือบันทึก JSON มีผลเฉพาะชุดที่เลือก

**เปลี่ยนชื่อ** เปลี่ยนเฉพาะชื่อชุด ชื่อตัดช่องว่างหัวท้าย ต้องไม่ว่าง ยาวไม่เกิน 80 ตัวอักษร และไม่ซ้ำชื่อชุดอื่น (แยกตัวพิมพ์เล็ก/ใหญ่) ผลสำเร็จและข้อผิดพลาดของชุดกฎจะแสดงข้างปุ่มในแผงนี้

**ลบชุด** จะแสดงคำเตือนระบุชื่อชุดและการลบไฟล์ที่ไม่มีชุดอื่นใช้ภายในแผงเดียวกัน ต้องกด **ยืนยันลบชุด** จึงจะลบ หรือกด **ยกเลิก** เพื่อกลับโดยไม่เปลี่ยนข้อมูล ระหว่างรอยืนยันจะปิดการเลือกชุด แก้กฎ นำเข้า และการทำงานอื่นใน popup แต่ยกเลิกได้เสมอ ไม่อนุญาตให้ลบชุดสุดท้าย หลังลบจะเลือกชุดแรกที่เหลือ หากหน้าต่างอื่นเปลี่ยนชุดกฎระหว่างรอยืนยัน จะยกเลิกการยืนยันและแจ้งให้เปิด popup ใหม่ก่อนเขียนข้อมูล

ต้องบันทึกหรือยกเลิกร่างในตัวช่วย/JSON ก่อนเลือก คัดลอก เปลี่ยนชื่อ หรือลบชุด หากมี popup อื่นเปลี่ยนข้อมูล จะหยุดการเขียนทับและยังเก็บร่างในหน้าต่างเดิมไว้ คัดลอกร่างที่ต้องการเก็บก่อนเปิด popup ใหม่ โหลดข้อมูลล่าสุดแล้วค่อยแก้ต่อ การปิด popup ยังทำให้ร่างที่ไม่บันทึกหายตามเดิม

กฎเดิมใน `chrome.storage.local.rules` ใช้เป็น **ค่าเริ่มต้น** แบบอ่านอย่างเดียวจนกว่าจะเปลี่ยนชุดหรือแก้ข้อมูลครั้งแรก จากนั้นเก็บข้อมูลที่ตรวจแล้วใน `chrome.storage.local.presetState` เพียงก้อนเดียว: `{ activeId, presets: [{ id, name, rules }] }` ไม่เขียนสำเนากฎที่เลือกกลับลง `rules` อีก หากข้อมูลชุดกฎผิดรูปแบบจะหยุดและไม่เขียนข้อมูลว่างทับ กฎและไฟล์เดิมยังอยู่เมื่อบันทึกล้มเหลว

ปุ่มกรอกและคีย์ลัดอ่านชุดที่เลือกจาก storage เมื่อเริ่มแต่ละรอบและใช้สำเนากฎนั้นตลอดรอบ ตัวเลือก **Next ใช้ร่วมกันทุกชุด** การคัดลอกชุดใช้ข้อมูลอ้างอิงไฟล์เดียวกันได้ จึงไม่ทำสำเนา bytes เพิ่ม การแก้/ลบกฎหรือลบชุดจะบันทึกก่อน แล้วจึงลบไฟล์ที่ไม่มีชุดใดเหลือใช้อยู่

## เริ่มใช้งาน

1. เปิด Google Forms **หน้าสำหรับตอบหรือหน้าตัวอย่าง** บน `docs.google.com` เช่น `/forms/d/e/.../viewform` หรือ `/forms/d/.../preview` ไม่ใช้หน้าแก้ไขหรือหน้าผลลัพธ์
2. เปิดส่วนขยาย กด **อ่านคำถามจากฟอร์ม** แล้วเลือกคำถามจากรายการ ระบบจะใส่ชื่อและเลือก **ตรงกับชื่อคำถาม** ให้ หรือพิมพ์ชื่อคำถามเองได้หากอ่านจากหน้านั้นไม่ได้
3. ใส่คำตอบ เลือก **คำตอบเดียว** สำหรับข้อความ (ขึ้นบรรทัดใหม่ได้), **หลายตัวเลือก (บรรทัดละข้อ)** สำหรับ checkbox หรือ **วันเกิด / วันที่** แล้วกด **เพิ่มและบันทึกกฎ** จะบันทึกทันทีโดยไม่ต้องกดบันทึกทั้งชุดอีก
4. กฎที่บันทึกจะแสดงชื่อและคำตอบย่อ กด **แก้ไข** เพื่อเปลี่ยนเฉพาะกฎนั้นแล้วบันทึก หรือ **ลบ** เพื่อลบเฉพาะรายการนั้น ปุ่ม **ยกเลิกการแก้ไข / ยกเลิกร่าง** คืนสู่การเพิ่มกฎโดยไม่เปลี่ยนกฎที่บันทึก
5. กด **อ่านคำถามจากฟอร์ม** อีกครั้งเพื่อตรวจการจับคู่ ดูชื่อคำถาม เลขกฎ และสถานะด้านล่าง โดยยังไม่กรอกหรือคลิกตัวเลือก แล้วกด **กรอกหน้านี้** ตรวจคำตอบบนแบบฟอร์มด้วยตนเองก่อนดำเนินการต่อ
6. ถ้ามีหลายส่วน ให้กด Next เอง หรือเปิดตัวเลือก Next เฉพาะคีย์ลัดด้านล่าง แล้วอ่านคำถามใหม่เมื่อถึงหน้าถัดไป รายการคำถามครอบคลุมเฉพาะหน้าปัจจุบันที่อ่านล่าสุด

**ตรงกับชื่อคำถาม** ใช้ชื่อทั้งข้อ เหมาะกับการแยกเบอร์โทรศัพท์ของตนเองกับเบอร์ฉุกเฉิน ส่วน **มีคำนี้ในชื่อคำถาม** ใช้คำธรรมดาที่อยู่ในชื่อและอาจตรงหลายข้อ ทั้งสองแบบตัดเลขข้อ/เครื่องหมายบังคับตอบและ escape เครื่องหมายพิเศษให้ ไม่ต้องเขียน Regex ไม่มีการเดาหรือจับคู่แบบคล้ายกัน

กฎเริ่มต้นเป็น `[]` เพื่อไม่กรอกข้อมูลใด ๆ ก่อนคุณตั้งค่า ไฟล์ `example-rules.json` เป็นข้อมูลสมมติทั้งหมด ใช้ดูรูปแบบหรือนำเข้ากับแบบฟอร์มทดสอบ แล้วเปลี่ยนเป็นคำตอบที่ต้องการ

ขณะมีร่างในตัวช่วย ต้องบันทึกหรือยกเลิกก่อนเลือกกฎอื่น ลบ นำเข้า แก้ JSON หรืออ่าน/กรอกฟอร์ม หากกำลังแก้ JSON ต้องบันทึกหรือกด **ยกเลิกแก้ JSON** ก่อนใช้ตัวช่วยหรือนำเข้าไฟล์ เพื่อไม่ให้ร่างหายหรือแก้ผิดรายการ ข้อมูลผิดหรือบันทึกล้มเหลวจะไม่แทนกฎเดิม การปิด popup ทำให้ร่างที่ยังไม่บันทึกหายไป คีย์ลัดและปุ่มส่งออกใช้กฎที่บันทึกล่าสุดเสมอ

## วันเกิด / วันที่: บันทึกกฎเดียวใช้ได้สองชนิดช่อง

เลือก **วันเกิด / วันที่** แล้วป้อนวัน/เดือน/ปี เช่น `29/02/2543` เลือก **ปีที่ป้อน → พ.ศ.** (ค่าเริ่มต้น) หรือป้อน `29/02/2000` แล้วเลือก **ค.ศ.** วัน/เดือนใช้ 1–2 หลัก ปีใช้ 4 หลัก ด้วยเลข 0–9 ระบบจะแสดงตัวอย่างก่อนบันทึกและปฏิเสธวันที่ไม่มีจริง เช่น 29 กุมภาพันธ์ 2566

กฎเดียวกันจะกรอกช่องวันที่ native เป็น `2000-02-29` (ค.ศ. ISO) เสมอ สำหรับช่องข้อความสั้น/ยาว เลือก **รูปแบบวันที่ในช่องข้อความ** ได้สามแบบ: **ตัวเลข** → `29/02/2543` (ค่าเริ่มต้น), **เดือนภาษาไทยเต็ม** → `29 กุมภาพันธ์ 2543` หรือ **เดือนภาษาไทยย่อ** → `29 ก.พ. 2543` ชื่อเดือนใช้วันไม่เติมศูนย์ ช่องว่างปกติ และเลข 0–9

เลือก **ปีสำหรับช่องข้อความ → พ.ศ. / ค.ศ.** แยกจากรูปแบบได้ เช่น วันสมมติ `18/04/2533` เลือกเดือนเต็มและ พ.ศ. จะได้ข้อความสั้น `18 เมษายน 2533`; เลือก ค.ศ. จะได้ `18 เมษายน 1990` ตัวอย่างสดแสดงทั้งค่าช่องวันที่และช่องข้อความก่อนบันทึก ไม่ต้องแก้ JSON

เมื่อแก้กฎ ตัวช่วยแสดงวันที่ป้อนเป็นตัวเลข DD/MM/YYYY ปี พ.ศ. อีกครั้ง โดยคงวันจริง ปีและรูปแบบสำหรับช่องข้อความที่บันทึกไว้ รองรับช่วง **ค.ศ. 0001–9456 / พ.ศ. 0544–9999** ใช้ พ.ศ. = ค.ศ. + 543 โดยไม่แปลงเขตเวลา กฎวันที่แบบข้อความเดิมยังกรอกตามตัวอักษรทุกตัว หากต้องการแปลงตามชนิดช่อง ให้แก้กฎแล้วเปลี่ยนเป็น **วันเกิด / วันที่** เอง ไม่มีการแปลงกฎเดิมอัตโนมัติ

```json
[{"pattern":"^วันเกิด$","flags":"iu","value":{"type":"date","iso":"2000-02-29","textCalendar":"buddhist","textFormat":"thai-long"}}]
```

ออบเจ็กต์วันที่ต้องมี `type: "date"`, `iso` แบบ ค.ศ. `YYYY-MM-DD` ที่มีอยู่จริง และ `textCalendar` เป็น `"buddhist"` หรือ `"gregorian"` เพิ่มได้เฉพาะ `textFormat` เป็น `"numeric"`, `"thai-long"` หรือ `"thai-short"` **ถ้าไม่ระบุ textFormat ยังคงเป็น DD/MM/YYYY เดิม** ตัวช่วยไม่เพิ่มคีย์นี้เมื่อแก้กฎตัวเลขเก่าตามปกติ และคงค่า numeric ที่ระบุไว้ชัดเจนในไฟล์นำเข้า กฎเก่าแบบข้อความ/อาร์เรย์ยังนำเข้าและส่งออกได้เหมือนเดิม

รองรับสามรูปแบบนี้เท่านั้น ไม่มีเทมเพลต เลขไทย การป้อนชื่อเดือน การเดารูปแบบจากคำถาม หรือการย้าย/แปลงข้อมูลอัตโนมัติ ช่องชนิดอื่นจะข้าม

## ไฟล์จากเครื่อง (1.5.0)

เลือก **ไฟล์จากเครื่อง** แล้วเลือกไฟล์ผ่านช่องเลือกไฟล์ของเบราว์เซอร์ หนึ่งไฟล์ต่อกฎ ไม่เกิน **10 MiB (10,485,760 bytes)** ชื่อและขนาดจะแสดงในร่าง การเลือกหรือยกเลิกร่างยังไม่เก็บไฟล์ เมื่อบันทึกกฎจึงเก็บ **สำเนา** ใน IndexedDB ของส่วนขยาย แก้ชื่อคำถาม/regex ได้โดยไม่ต้องเลือกไฟล์ซ้ำ การแก้ไฟล์ต้นฉบับบนดิสก์ไม่เปลี่ยนสำเนา ต้องเลือกใหม่และบันทึกเพื่อแทนที่ ไม่มีช่องพิมพ์ path และไม่ตีความคำตอบข้อความเป็น path

**เมื่อกดกรอกหรือคีย์ลัด สำเนานี้จะถูกอัปโหลดไป Google ผ่าน picker ของคำถามที่ตรงกฎ** และอาจถูกเก็บใน Google Drive ตามพฤติกรรมของ Google Forms ตรวจชื่อคำถามและไฟล์ก่อนใช้งาน อ่านคำถาม/dry-run ตรวจข้อมูลอ้างอิงและสำเนาเท่านั้น ไม่เปิด picker ไม่ส่ง bytes เข้าเว็บ ไม่อัปโหลด รวมไฟล์ไม่ซ้ำต่อครั้งไม่เกิน **20 MiB ก่อนเข้ารหัส base64** ไฟล์เดียวที่หลายกฎ/หลายคำถามใช้ส่ง bytes เพียงชุดเดียว แต่แต่ละคำถามยังต้องแนบแยกกัน

JSON มีเพียงข้อมูลอ้างอิงรูปแบบนี้ (UUID ตัวอย่างไม่มีไฟล์จริง):

```json
{"type":"file","fileId":"b0c51dee-4347-4f82-85de-a070a975db82","name":"TEST-ONLY.pdf","size":4,"mime":"application/pdf"}
```

ข้อมูลอ้างอิงมีเฉพาะ `type`, UUID v4 `fileId`, ชื่อไฟล์ไม่ใช่ path `name` (ไม่เกิน 255 ตัวอักษร), จำนวนเต็ม bytes `size` และ `mime` หรือข้อความว่าง ไม่มี bytes/base64 ในกฎ Worker หรือ JSON ส่งออก การนำเข้ากลับใน **ส่วนขยาย/โปรไฟล์เดิม** ใช้สำเนาที่เก็บอยู่ได้ แต่ JSON ในเครื่องหรือโปรไฟล์อื่นสร้างเนื้อไฟล์คืนเองไม่ได้ และสำเนาที่ถูกลบแล้วคืนจาก JSON ไม่ได้ หากไม่พบหรือ metadata ไม่ตรงจะแสดง **เลือกไฟล์ใหม่** และยังไม่กรอก/อัปโหลด

เมื่อแทนไฟล์จะเก็บ record ใหม่ก่อนบันทึกกฎ หากบันทึกล้มเหลวจะพยายามลบเฉพาะ record ใหม่ กฎและไฟล์เก่ายังอยู่ หลังบันทึกสำเร็จจึงลบสำเนาเก่าที่ไม่มีกฎในทุกชุดที่เหลืออ้างอิง รวมถึงชุดที่ไม่ได้เลือกและ reference ที่ใช้ร่วมกัน/นำเข้า ไม่มีการกวาดลบข้อมูลอื่นอัตโนมัติ หาก IndexedDB ใช้ไม่ได้/เต็มจะแจ้งข้อผิดพลาด หาก cleanup ล้มเหลวอาจมีสำเนาที่ไม่ได้ใช้เหลืออยู่ การถอนส่วนขยาย/ล้างข้อมูลอาจทำให้สำเนาหาย ต้องเลือกไฟล์ใหม่

รองรับการ์ดคำถามที่มี `role=list` ชื่อ **Selected files** (หรือ **ไฟล์ที่เลือก**) และปุ่ม **Add file / เพิ่มไฟล์** ที่ตรงทั้งข้อความและเปิดใช้งาน คลิกได้ครั้งเดียวต่อคำถาม ต้องเป็น picker ใหม่ใน dialog ที่มี iframe ต้นทางเดียวกันและ pathname `/picker` (บนเว็บจริงคือ `https://docs.google.com/picker`) มี dialog **Insert file** และ file input เพียงหนึ่งตัว ไม่ใช้ชื่อ iframe แบบสุ่มหรือ query/auth parameters ไม่เรียก Google API ภายใน ไม่อ่าน tokens ไม่เพิ่ม permissions

ตรวจ accept ตาม MIME/นามสกุลและ single-file constraint ก่อนใช้ `File`/`DataTransfer` ของ iframe นับสำเร็จ **เฉพาะเมื่อพบชื่อไฟล์ตรงทั้งชื่อในรายการแนบที่มองเห็นของคำถามด้านนอก และ picker ที่เปิดเองซ่อน/ปิดแล้ว โดยไม่มี modal หรือ progress ที่มองเห็นค้างอยู่** ไม่ใช้ input.files หรือ progress เป็นหลักฐาน หากชื่อไฟล์ขึ้นก่อน picker ปิดจะรอภายในเวลางานเดิม หาก picker ปิดก่อนรายการแนบขึ้นจะรอรายการอีกไม่เกิน 5 วินาทีโดยไม่เปิด picker ซ้ำ หากต้องยืนยัน รองรับเฉพาะ **Insert / Insert 1 item** ที่มีรายการเลือกตรงชื่อไฟล์อย่างชัดเจน ภาษา/layout อื่นให้ทำเอง

ปุ่ม Add file อนุญาต `aria-labelledby` ที่อ้างถึงคำถามเมื่อข้อความ/aria-label ตรงตามเงื่อนไขเดิม (ไม่เปลี่ยนข้อจำกัดของ Next) อนุญาต file input ที่ซ่อนอยู่เฉพาะภายใน picker ใหม่ที่ตรวจแล้ว และไม่ใช้ iframe เก่าที่ซ่อนอยู่แม้ยังคงอยู่ใน DOM

รอ document ของ picker เป็น `readyState="complete"` มี input เดียว ปุ่ม Browse ที่มองเห็นและใช้งานได้ และไม่มี busy/progress จากนั้นรอ UI ของ picker ที่เปิดเองนิ่งอย่างน้อย 1 วินาที การเปลี่ยน DOM จะเริ่มนับใหม่ และหยุดหาก document/frame/dialog หรือเจ้าของฟอร์มเปลี่ยน เฉพาะก่อนกำหนดไฟล์ครั้งแรก หาก Google แทน input จะเลือก input ใหม่ที่เชื่อมต่ออยู่เพียงตัวเดียวภายใน document/dialog เดิมและเริ่มนับเวลานิ่งใหม่ หลังเริ่มกำหนดไฟล์จะไม่เลือก input ใหม่หรือส่งซ้ำ การค้นหาและรอนิ่งใช้เวลาร่วมกับการยืนยันไฟล์ภายใน 60 วินาทีต่อไฟล์และเพดานรวม 180 วินาทีเดิม ตรวจซ้ำก่อนส่งไฟล์ครั้งเดียว ไม่มีสัญญาณ DOM ใดรับประกันว่า Google เริ่มระบบภายในครบแล้ว ผลทดสอบจริงจำกัดตามสถานการณ์ท้ายเอกสาร และยังต้องยืนยันชื่อไฟล์ด้านนอกพร้อม picker ปิดตามเงื่อนไขข้างต้น

รายการว่างที่ข้ามได้จำกัดเฉพาะ `div[role="listitem"][data-tooltip]` ไม่มี child node/ข้อความ มี `jscontroller="By0w6"` และ `jsaction` ตามรูปแบบ Remove file ที่พบจริง พร้อมเฉพาะ attributes ที่รู้จัก ไม่ลบหรือเปลี่ยน node นี้ รายการมีข้อความ มีลูก มีตัวควบคุม มี busy/progress หรือไม่รู้จักจะยังถือว่ามีรายการเดิม

มีไฟล์ในรายการเดิมจะเก็บไว้เสมอ ไม่ลบหรือแทนที่บน Google Form หาก picker เปิดอยู่แล้ว เข้าถึงไม่ได้ ต้นทางไม่ตรง มีหลาย picker ชนิดไฟล์ไม่รับ หน้า/คำถามเปลี่ยน ยกเลิก หรือยืนยันไฟล์ไม่ได้ จะให้ตรวจ/แนบเอง ไม่อัปโหลดคำถามไฟล์ถัดไปและไม่กด Next แม้เปิด override ตัวเลือก Next จะไม่พาออกจาก modal หรืองานอัปโหลดที่ยังค้าง

การอัปโหลดผ่าน popup และคีย์ลัดจริงหลัง Reload ส่วนขยาย 1.6.2 ใน Opera ผ่านทั้งสามสถานการณ์ที่ระบุด้านล่าง ผลนี้ไม่ยืนยันการทำงานหลังปิด popup, service-worker idle suspension, auto-Next หรือ Chrome และไม่รับประกัน Google Forms ทุกแบบ

## ขั้นสูง: Regex / JSON / นำเข้า–ส่งออก

ในตัวช่วย เลือก **Regex (ขั้นสูง)** เพื่อใส่ source และ flags เอง กฎ Regex จากไฟล์เดิมที่ซับซ้อนจะแสดงโหมดนี้ โดยเก็บ source และ flags ไว้เมื่อแก้เฉพาะคำตอบ ระบบจะแสดงกฎเดิมเป็นชื่อธรรมดาเฉพาะเมื่อแปลงกลับได้ตรงทุกตัวอักษร

เปิดหัวข้อ **ขั้นสูง: JSON / นำเข้า–ส่งออก** เพื่อวาง JSON แล้วกด **บันทึก JSON** หรือ **นำเข้า JSON ในช่อง** หรือนำเข้าไฟล์ผ่าน **นำเข้าไฟล์ JSON** การบันทึก/นำเข้าทางนี้ตรวจทั้งชุดแล้วแทนกฎเฉพาะชุดที่เลือก หากผิด กฎเดิมยังอยู่ ใช้ **ยกเลิกแก้ JSON** เพื่อคืนข้อความที่บันทึกไว้ **ส่งออกชุดที่เลือก** ส่งออกกฎที่บันทึกเป็น array รูปแบบเดิม ไม่รวมชื่อชุด ชุดอื่น หรือการตั้งค่า Next กฎจากตัวช่วยกับ JSON ใช้ข้อมูลชุดเดียวกัน โดย value รองรับข้อความ อาร์เรย์ วันที่ และข้อมูลอ้างอิงไฟล์ (ไม่มีเนื้อไฟล์)

ตัวช่วยไม่อนุญาตให้เพิ่มกฎที่มี pattern และ flags ซ้ำกับกฎเดิม แต่ยังอ่านและแก้คำตอบของข้อมูลเก่าที่มีรายการซ้ำได้ หากหลายกฎตรงคำถามเดียวกัน ระบบจะข้ามข้อนั้นตามเดิม

## คีย์ลัด

- Windows / Linux: **Alt+Shift+F**
- macOS: **Option+Shift+F**

นี่คือคีย์เริ่มต้นที่แนะนำ การติดตั้ง Opera เดิมอาจเก็บคีย์ลัดที่ตั้งไว้แม้ Reload แล้ว บน macOS ให้เปิด `opera://extensions/shortcuts` หรือ **Extensions → Keyboard shortcuts** เลือก **Regex Form Filler → fill-form** (คำสั่งกรอก Google Forms ด้วยกฎที่บันทึกไว้) แล้วตั้งเป็น **Option+Shift+F** จากนั้นเปิด popup ใหม่เพื่อตรวจ **คีย์ลัดที่ใช้งานจริง** อย่าคาดว่า Reload จะเปลี่ยนคีย์ให้ และ **ห้ามถอนส่วนขยายเพื่อตั้งคีย์ใหม่** เพื่อรักษากฎและสำเนาไฟล์เดิม

คีย์ลัดกรอกหน้าปัจจุบันด้วยกฎที่บันทึกไว้ ใช้โค้ดเดียวกับปุ่มกรอก มีข้อความสั้นบนหน้าและตัวเลขบนไอคอนส่วนขยาย เปิด popup เพื่อดูผลแต่ละข้อได้ ผลตรวจอย่างเดียวแสดง badge `DRY` และข้อผิดพลาดระดับงานแสดง `!`

popup อ่านคีย์ลัดที่เบราว์เซอร์กำหนดจริงผ่าน `commands.getAll` หากไม่ถูกกำหนดจะแสดงคำเตือน คีย์ของระบบหรือเบราว์เซอร์อาจชนกัน ให้เปิด `opera://extensions/shortcuts` แล้วเปลี่ยนคีย์ของ Regex Form Filler หาก Opera รุ่นที่ใช้เปิด URL นี้ไม่ได้ ให้ไป **Extensions → Keyboard shortcuts** (ชื่อเมนูอาจต่างกันตามรุ่น/ภาษา) ใน Chrome ใช้ `chrome://extensions/shortcuts`

เอกสาร Opera อธิบาย Commands API และการชนกับคีย์ของเบราว์เซอร์ แต่ไม่ได้รับประกัน URL หน้าตั้งค่าสำหรับทุกรุ่น จึงมีทางเลือกผ่านเมนูด้านบน

## Next เฉพาะคีย์ลัด (1.4.0)

ทั้งสองตัวเลือกเริ่มต้น **ปิด** และบันทึกทันทีเมื่อเปลี่ยน:

- **กด Next อัตโนมัติเมื่อกรอกครบ** — หลังคีย์ลัดกรอกสำเร็จ ตรวจคำตอบจริงทุกคำถามที่มองเห็นในหน้าปัจจุบัน รวมข้อไม่บังคับ ข้อไม่ตรงกฎ คำตอบเดิม และคำตอบที่กรอกเอง ไม่ใช้จำนวนกฎที่ตรงหรือจำนวนข้อที่กรอกเป็นตัวตัดสิน
- **อนุญาต Next แม้ยังกรอกไม่ครบ** — เลือกได้เมื่อเปิดข้อแรกเท่านั้น อนุญาตให้ลอง Next แม้มีคำถามว่าง/ตรวจไม่ได้ แต่ไม่ข้ามการตรวจฟอร์มหรือเบราว์เซอร์ คำตอบบังคับหรือค่าที่ไม่ถูกต้องอาจทำให้ยังอยู่หน้าเดิม ปิดข้อแรกแล้วข้อสองไม่มีผลแม้เคยบันทึกเป็นเปิด

ปุ่ม **กรอกหน้านี้**, **อ่านคำถามจากฟอร์ม** และ dry-run ใน popup ไม่กด Next เสมอ คีย์ลัดแต่ละครั้งลองคลิกได้ **ไม่เกิน 1 ครั้ง** เฉพาะหน้าที่เริ่มกรอก ไม่วน ไม่กรอกหน้าถัดไป ไม่กด Enter ไม่เรียก submit/requestSubmit และ **ไม่กด Submit / ส่ง**

รองรับปุ่มที่มีข้อความตรงทั้งปุ่มเป็น **Next** หรือ **ถัดไป** เท่านั้น ต้องเห็น เปิดใช้งาน อยู่นอกการ์ดคำถามและใน form เดียวกัน มีเพียงปุ่มเดียว ชื่อ accessibility ต้องไม่ขัดกับข้อความ ปุ่ม native submit แม้ชื่อ Next ก็ไม่ใช้ ไม่รองรับภาษาอื่นหรือปุ่มที่ต้องตีความชื่อจาก aria-labelledby

การตรวจครบรองรับ native text/email/tel/number/url/date, textarea, select แบบเลือกเดียว และ radio/checkbox ที่เลือกคำตอบที่ถูกต้องอย่างน้อยหนึ่งตัวเลือก (radio เลือกได้หนึ่งข้อ) รองรับ custom radio/checkbox ผ่าน aria-checked และ listbox แบบ local options/data-value ตามรูปแบบที่ตัวกรอกเดิมรองรับ ช่องข้อความที่มีแต่ช่องว่าง ค่าที่ไม่ผ่าน validity/aria-invalid และ optional ที่ว่างถือว่ายังไม่ครบ ตาราง/grid widget ไม่รู้จัก การ์ดที่อ่านชื่อคำถามไม่ได้ หรือกลุ่มหลายช่องที่ตีความไม่ชัดเจนถือว่า **ยังไม่ครบ** ให้ใช้ override หรือกด Next เอง ไฟล์นับครบเมื่อพบรายการแนบใน Selected files เท่านั้น; งานไฟล์ที่ยืนยันไม่ได้ห้าม Next แม้ override · ไม่นับ role=list ที่ครอบคำถาม การ์ดหัวข้อส่วนระดับ 1/2 ที่ไม่มีคำถาม/ช่องตอบ และแถวไฟล์แนบที่ซ้อนอยู่เป็นคำถาม · native radio/checkbox ที่มองเห็นต้องผ่าน validity ทุกตัว รวม checkbox บังคับที่ยังไม่เลือก ส่วนตัวเลือกปิดใช้งานที่ไม่ได้เลือกไม่ขัดขวางการตรวจครบ

เมื่อ URL/document หรือชุดการ์ด/ช่องคำถามเปลี่ยน หรือมีผล stale/error/timeout จะไม่ลอง Next แม้เปิด override หลักฐานหน้าเดิมใช้ได้ครั้งเดียวและถูกล้างหลังจบงาน ผล Next แยกจากรายงานการกรอก: ยังไม่ครบ, ไม่พบปุ่ม, ปุ่มปิดใช้งาน, หลายปุ่ม, หน้าเปลี่ยน, ตรวจ/คลิกไม่สำเร็จ หรือ **ลองกด Next แล้ว 1 ครั้ง** คำว่า “ลองกด” ไม่ยืนยันว่าเปลี่ยนหน้าสำเร็จ และไม่ลองกรอก/คลิกซ้ำหากรายงานการนำทางล้มเหลว

ตัวเลือกเก็บใน `chrome.storage.local.shortcutOptions` แยกจาก `presetState` และใช้ร่วมกันทุกชุด รับเฉพาะ boolean `true`; ค่าที่ไม่มีหรือผิดรูปแบบปิดอย่างปลอดภัย การเปลี่ยนตัวเลือกไม่บันทึกหรือล้างร่างกฎ/JSON และแสดงสถานะสำเร็จหรือล้มเหลวพร้อมคืน checkbox เดิมเมื่อบันทึกไม่ได้ **นำเข้า/ส่งออก JSON มีเฉพาะกฎของชุดที่เลือก ไม่รวมตัวเลือกคีย์ลัด** กฎที่บันทึกไว้เดิมคงอยู่โดยไม่ต้องนำเข้าใหม่

## รูปแบบกฎ

```json
[
  {"pattern":"^ชื่อจริง$","flags":"iu","value":"ทดสอบ"},
  {"pattern":"^(?!.*ฉุกเฉิน).*เบอร์โทรศัพท์.*$","flags":"iu","value":"0000000000"},
  {"pattern":"^.*เบอร์โทรศัพท์.*ฉุกเฉิน.*$","flags":"iu","value":"0000000001"},
  {"pattern":"^E-mail$","flags":"iu","value":"regex-test@example.com"},
  {"pattern":"^กิจกรรมทดสอบ$","flags":"iu","value":["อ่าน","เดิน"]}
]
```

- `pattern`: regex source ไม่ใส่ `/.../` ครอบ เช่น `^ชื่อจริง$` เครื่องหมาย `^` และ `$` ช่วยระบุชื่อทั้งข้อ
- `flags`: ใช้ `i`, `m`, `s`, `u` อย่างละไม่เกินหนึ่งครั้ง ถ้าไม่ระบุจะเป็น `iu` ไม่อนุญาต `g` หรือ `y`
- `value`: ข้อความ รวมทั้งเลขอายุและโทรศัพท์; checkbox ใช้ข้อความหรืออาร์เรย์ข้อความ; วันที่ที่ต้องการแปลงตามชนิดช่องใช้ออบเจ็กต์ `{type, iso, textCalendar}` โดยเพิ่ม `textFormat` ได้ตามตัวอย่างด้านบน
- ใน JSON ต้องเขียน backslash สองตัว เช่น regex `\s` เขียนเป็น `"\\s"`
- หากคำถามตรง **หลายกฎ** จะข้ามและแสดงเลขกฎทั้งหมด ไม่เลือกกฎแรกให้อัตโนมัติ
- ตัวเลือก radio / checkbox / dropdown ต้องตรงทั้งข้อความหลังทำ NFC และรวมช่องว่าง ไม่ใช้ regex จับคู่ตัวเลือก

ชื่อคำถามมาจาก `role="heading" aria-level="3"` ภายใน `role="listitem"` เท่านั้น ไม่รวมชื่อส่วน คำอธิบาย หรือข้อความตัวเลือก ชื่อจะทำ Unicode NFC รวมช่องว่าง/NBSP ตัด `*` ท้ายชื่อ และตัดเลขนำหน้ารูปแบบ `9. `, `9) `, `๙. ` หรือ `๙) ` โดยต้องมีช่องว่างหลังเครื่องหมาย จึงไม่ตัดเลขปกติอย่าง `3.14 คะแนน` หรือ `10 ปีที่ผ่านมา`

รองรับการนำเข้าข้อมูลเก่าแบบ `{"ชื่อจริง":"ทดสอบ"}` โดยแปลง keyword เป็น regex แบบ escape และยึดหัวท้าย ไม่ถือ keyword เป็น regex มีเพียง keyword `โรคประจำตัว` ที่อนุญาตคำขยายในวงเล็บท้ายชื่อเพื่อรองรับคำถามที่พบ เช่น `โรคประจำตัว (หากมี โปรดระบุ ...)` ไฟล์ส่งออกใช้รูปแบบ array เสมอ และเก็บอักษรไทย/Unicode ตามเดิม

## ขอบเขตที่รองรับ

- ช่อง native `text`, `email`, `tel`, `number`, `url`, `textarea` และวันที่ `date`
- ช่อง native date ใช้ **ค.ศ. ISO `YYYY-MM-DD`** แม้เบราว์เซอร์แสดงวันที่ตามภาษา กฎชนิดวันที่แปลงช่อง text/textarea เป็นตัวเลข `DD/MM/YYYY`, เดือนภาษาไทยเต็ม หรือย่อ ตามปีที่เลือก; กฎข้อความเดิมไม่แปลงค่า
- native radio / checkbox / select แบบเลือกค่าเดียว และ Google Forms radio / checkbox ที่มี `aria-checked`
- Google Forms dropdown แบบ `role="listbox"` ที่มีตัวเลือกอยู่ภายใน พร้อม `data-value` และสถานะเริ่มต้นที่ยืนยันได้ หาก DOM ไม่อยู่ในรูปแบบนี้จะข้ามให้กรอกเอง
- ใช้ native setter และส่ง `input` / `change` สำหรับช่อง native จากนั้นอ่านค่าและตรวจ validity ส่วน custom controls คลิกแล้วตรวจสถานะกลับ หากไม่ตรงจะรายงานว่าไม่ผ่าน
- ถ้าช่องมีคำตอบหรือมีตัวเลือกเลือกอยู่แล้วจะเก็บของเดิมทั้งข้อนั้น แม้ค่าจะไม่ตรงกับกฎ ไม่มีโหมดเขียนทับ
- รองรับไฟล์ตามรูปแบบ picker ด้านบน; ข้ามรหัสผ่าน ตาราง/grid คำถามหลายช่องในข้อเดียว (รวมตัวเลือก “อื่น ๆ” ที่มีช่องข้อความ) native select แบบหลายค่า และ custom widget ที่ยืนยันสถานะไม่ได้
- ไม่กรอกช่องซ่อน/ปิดใช้งาน/อ่านอย่างเดียว ไม่คลิกข้อตกลงที่ไม่มีกฎตรงกับชื่อคำถาม อัปโหลดเฉพาะสำเนาไฟล์ที่เลือกและบันทึกไว้เมื่อกดกรอก/คีย์ลัด ไม่ส่งแบบฟอร์ม · ลองกด Next ได้เฉพาะคีย์ลัดเมื่อเปิดตัวเลือกด้านบน

ควรใช้กฎเจาะจง โดยเฉพาะเบอร์โทรศัพท์ของตนเองกับผู้ติดต่อฉุกเฉิน กฎกว้างอย่าง `.*` อาจตรงคำถามข้อตกลงหรือคำถามที่คุณไม่ได้ตั้งใจ

ผลหลังคลิกเป็นการตรวจสถานะ DOM ณ เวลานั้น ไม่รับประกันว่าหน้าเว็บจะไม่เปลี่ยนค่าภายหลัง หากบางตัวเลือกในข้อ checkbox เปลี่ยนสำเร็จก่อนพบความผิดพลาด อาจเหลือคำตอบบางส่วน ให้ตรวจข้อนั้นเองก่อนลองใหม่ ส่วนขยายจะไม่ลบคำตอบเพื่อย้อนการทำงาน

## การจำกัดเวลาและข้อมูล

ใช้สิทธิ์เพียง `activeTab`, `scripting`, `storage` การอ่าน/กรอกเริ่มเมื่อคุณกดส่วนขยายหรือคีย์ลัด ไม่มี content script ประจำทุกเว็บ ไม่มี host permissions และไม่ใช้ MAIN world

เนื่องจาก service worker ของส่วนขยายไม่สามารถเป็นหน้าต่างเจ้าของ dedicated Worker ได้ การตรวจแต่ละครั้งจะเปิด **แท็บส่วนขยายชั่วคราวที่ไม่แย่งโฟกัส** เพื่อสร้าง bundled Worker แล้วปิดแท็บเมื่อเสร็จ ไม่ต้องเพิ่มสิทธิ์ `tabs` หรือ `offscreen` ตัว regex ไม่ทำงานบนเธรด DOM ของแบบฟอร์มหรือ popup หากทำงานเกิน 1.5 วินาทีจะ terminate Worker โดยยังไม่เริ่มกรอก ถ้าแท็บตรวจไม่ตอบภายใน 10 วินาทีจะยกเลิกและปิดแท็บด้วย ขีดจำกัดการกรอก DOM ที่ไม่มีงานไฟล์คือประมาณ 15 วินาทีต่อครั้ง งานไฟล์รอไม่เกินประมาณ 60 วินาทีต่อไฟล์และรวม 180 วินาทีต่อครั้ง หากยืนยันไม่ได้จะหยุดงานไฟล์ที่เหลือและไม่กด Next ต้องตรวจ picker/รายการแนบด้วยตนเองก่อนเรียกใหม่ ไม่มีการลองอัปโหลดซ้ำอัตโนมัติ ปิด popup แล้ว background ยังทำงานต่อ (ยังต้องยืนยัน lifecycle ในส่วนขยายที่ติดตั้งจริง)

จำกัด 100 กฎต่อชุด, pattern 512 ตัวอักษร, value 8192 ตัวอักษร, checkbox 50 ตัวเลือก, JSON 262144 ตัวอักษรต่อชุด (ไฟล์นำเข้าไม่เกิน 256 KiB) และคำถามที่มองเห็นไม่เกิน 200 ข้อ ชื่อข้อละ 2000 ตัวอักษร จำนวนชุดรวมขึ้นอยู่กับพื้นที่ storage ของเบราว์เซอร์ เมื่อบันทึกไม่ได้จะเก็บข้อมูลเดิมไว้

กฎและคำตอบอยู่ใน `chrome.storage.local` และสำเนาไฟล์อยู่ใน IndexedDB ของส่วนขยาย **แบบไม่เข้ารหัส** ไม่ใช้ sync ผลล่าสุดของแต่ละแท็บอยู่ใน session storage มีชื่อคำถาม เลขกฎ สถานะ วันเวลา เวอร์ชันที่รัน และรหัส diagnostic ที่อยู่ใน allowlist เท่านั้น ไม่มีค่าคำตอบ ชื่อไฟล์ fileId หรือ bytes ในรายงานหรือ console logs (ชื่อคำถามยังอยู่ตามเดิม) ไฟล์ JSON ที่ส่งออกมีคำตอบ/ข้อมูลอ้างอิงไฟล์ จึงควรเก็บเป็นส่วนตัว การกรอกอาจกระตุ้นระบบบันทึกร่างของ Google Forms ตามพฤติกรรมของเว็บไซต์ แต่ส่วนขยายไม่มีการส่งข้อมูลไปเซิร์ฟเวอร์ของตนเอง

## ไฟล์และการตรวจสอบสำหรับผู้พัฒนา

`background.js` รับทั้งคำสั่งคีย์ลัดและ popup, `core.js` ตรวจ schema/URL และ normalize, `presets.js` ตรวจชุดกฎและอ่าน legacy fallback ร่วมกันระหว่าง popup/background/preview, `form-dom.js` เก็บคำถามและกรอก DOM, `runner.html`/`runner.js` เป็นหน้าชั่วคราวสำหรับ `matcher.js`/`regex-worker.js`, ส่วน UI คือ `popup.html`/`popup.css`/`popup.js` และ `rule-editor.js` แปลงกฎกับตัวช่วยกรอก; `file-store.js` เก็บ/ตรวจสำเนาไฟล์และเตรียม payload ที่จำกัดขนาด

การแก้ชุดกฎใช้ Web Locks ชื่อ `regex-form-filler-presets` ร่วมกันทุก popup ของ origin เดียว แล้วอ่าน storage ซ้ำก่อนเขียนและ cleanup หากพบข้อมูลใหม่จะปฏิเสธการเขียนแทนการรวมอัตโนมัติ Storage-change listener แจ้งหน้าต่างที่เก่าให้เปิดใหม่ โดยไม่ลบร่าง ต้องใช้ Chromium ที่รองรับ Web Locks; ถ้า API ใช้ไม่ได้จะไม่บันทึกทับแบบไม่ล็อก

ชุดทดสอบและ fixture อยู่นอกโฟลเดอร์ส่งมอบที่ `work/regex-form-filler-tests/` จาก workspace root รัน:

```sh
node --test --test-concurrency=1 work/regex-form-filler-tests/*.test.mjs
python3 work/regex-form-filler-tests/preview-server.py --self-test
```

v1.6.3 ผ่าน Node tests 204/204 ข้อ พร้อม preview self-test และ diff check การเรียก shipping `formDOM` โดยตรงใน isolated context บนฟอร์มซ้อมจริงใน Opera อัปโหลด PDF ทดสอบสองไฟล์สำเร็จต่อเนื่องสองรอบปกติ (12.602 และ 9.916 วินาที) และรอบจำลอง network latency 12 วินาที (21.441 วินาที) ส่งไฟล์ครั้งเดียวต่อไฟล์ ไม่มี Next หรือ Submit ผลนี้ไม่ใช่การตรวจคีย์ลัดของส่วนขยาย v1.6.3 ที่ติดตั้งจริง และยังไม่ได้ทดสอบ Chrome, service-worker idle suspension หรือ auto-Next ในรุ่นนี้ ผล popup และคีย์ลัดจริงด้านล่างเป็นประวัติ 1.6.2 เท่านั้น

หลักฐานล้มเหลวซ้ำของ 1.6.2 บนฟอร์มจริงยังเก็บไว้เป็นประวัติ การทดสอบควบคุม network latency 12,000ms พบ `discovery.picker-deadline-after-poll` ที่ 10,061ms โดยยังเหลือเวลางานไฟล์และไม่มีการกำหนดไฟล์ ยืนยันเพดานค้นหาแยกที่สั้นเกินไปในรอบนั้นเท่านั้น รอบไม่ throttle ก่อนหน้าที่ล้มเหลวมีเพียง diagnostic ทั่วไป จึงยังสรุปว่าเป็นสาเหตุเดียวกันไม่ได้ หลักฐาน scratch อยู่ที่ `work/picker-controlled-slow-discovery.json` ของ parent และไม่รวมใน runtime ผลทดสอบอัตโนมัติไม่ยืนยันว่าแก้ปัญหาเป็นครั้งคราวทั้งหมดแล้ว

หลักฐานก่อนหน้า 1.6.2 วันที่ 15 ตุลาคม 2026: เรียก shipping `formDOM` ที่ serialize เข้า isolated context บน practice Google Form จริงใน Opera อัปโหลด `TEST-ONLY-1.pdf` และ `TEST-ONLY-2.pdf` ต่อกันในการเรียกครั้งเดียวได้ `filled/filled` และเห็นชื่อทั้งสองไฟล์ จากนั้นลบเฉพาะไฟล์ที่สอง ตรวจพบ empty tooltip leaf ที่ Google เก็บไว้ แล้วเรียกใหม่ได้ `preserved/filled` พร้อมชื่อทั้งสองไฟล์ ไม่มี Submit หลักฐานคือ `live-two-files.json`, `live-remove-refill.json` และ `live-two-files.jpg` นี่เป็นการเรียก function โดยตรง แยกจากผลส่วนขยายที่ติดตั้งด้านล่าง ชุดทดสอบ Node เดิมผ่าน 185 ข้อ พร้อม preview self-test และ diff check

หลังผู้ใช้ Reload ยืนยันเวอร์ชัน 1.6.2 ใน native popup แล้วทดสอบส่วนขยายที่ติดตั้งใน Opera บน practice Google Form จริง: (1) Popup Fill ในชุดสังเคราะห์แนบ `TEST-ONLY-2.pdf` เห็นชื่อไฟล์และรายงาน 1.6.2 เป็น filled 1/3 ข้อ ข้ออื่น unmatched (2) เพิ่ม `TEST-ONLY-1.pdf` ด้วย native chooser ในชุดทดสอบเดิม บันทึก 2 กฎ ลบ sample 2 ให้ช่องไฟล์ทั้งสองว่าง แล้วกด Option+Shift+F หนึ่งครั้ง ได้ `filled/filled` 2/3 ข้อและเห็นชื่อทั้งสองไฟล์ เวลา 2026-10-15 22:03:58 Asia/Bangkok (3) ลบ sample 2 อีกครั้ง แล้วกดคีย์ลัดหนึ่งครั้ง ได้ `preserved/filled` เวลา 22:04:41 ทั้งสามครั้งไม่พบ failure ไม่ Submit, Next ปิดตลอด และ consent ตั้งใจไม่จับคู่ หลักฐานคือ `installed-shortcut-two-files.jpg`, `installed-shortcut-report.txt` และ `installed-refill-report.txt`
